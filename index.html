What changed

Domo serves the custom-app document with a session cookie, ryuu_sid (SameSite=None; Secure). Everything under the app's /assets/ folder is gated on that cookie. Safari blocks third-party cookies outright, so the asset requests arrive with no Cookie header and Domo answers 403 — the JavaScript never loads and the card renders blank.

This design serves the same bundle, byte for byte, from /public-assets/ instead. Files there need no authentication, so they load regardless of cookie policy. Only the three references in index.html changed; no application code was touched.

  • Chrome worked either way, because it still sends third-party cookies. That is temporary.
  • Firefox worked either way, because it partitions the cookie rather than blocking it.
  • Safari on macOS and iOS was the failure, and iOS users cannot reasonably be asked to turn tracking protection off.

Domo precedent: DOMO-489157 (CSS and JavaScript Return 403 in Safari with Prevent Cross-Site Tracking Enabled) and DOMO-477179, closed NoRelease — a documented limitation with public-assets as the sanctioned workaround.
