Domo public embed — Safari ITP asset test

This page is served from github.io, a different site from domo.com, so the Domo embed below is a genuine third-party iframe. That is the condition that triggers Safari's Intelligent Tracking Prevention.

What you are looking at

The embedded Domo page holds two custom-app cards. Both run byte-identical application code. The only difference is where the build writes its external CSS and JS.

CardAssets served fromExpected in Safari
A — private assets /assets/index-*.js|css
cookie-gated, needs ryuu_sid		 403 — blank, unstyled
B — public-assets fix /public-assets/index-*.js|css
served unauthenticated		 200 — renders fully

How to read the result

  • Card B renders (dark panel, three metric tiles, teal and blue stacked bars) and card A is blank or unstyled → the fix works, ITP confirmed as the cause.
  • Both render → cross-site tracking prevention is switched off in this browser. On macOS: Safari → Settings → Privacy → Prevent cross-site tracking. On iOS: Settings → Apps → Safari → Prevent Cross-Site Tracking.
  • Both blank → something else is in the way; check the network log for the domoapps requests.

Chrome currently renders both, because it still sends third-party cookies. That is temporary. Firefox renders both because it partitions the cookie rather than blocking it.
